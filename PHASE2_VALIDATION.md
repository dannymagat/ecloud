## 1. Purpose and method

**What Phase 2 verified.** Nine specialist artifacts established, from local code (`ezecontroller`, `wlan-testing`, `EZEGATE`) and upstream sources (TIP wlan-ucentral-schema / wlan-ap / wlan-cloud-ucentralgw, f00b4r0/uspot, coova/coova-chilli, FreeRADIUS v3.2.x, wireguard.com, OpenWrt feeds), which enforcement, AAA, portal, tunnel and management mechanisms exist on the target stack, and designed ECLOUD around only those. The single most important finding is structural: **per-client bandwidth from RADIUS is verified only on the uspot captive path; the hostapd (802.1X / MAC-auth) path has no verified per-client rate mechanism; per-SSID `rate-limit` is the only verified device-wide cap; CoA/Disconnect is verified as a configuration path but not end-to-end.** Everything else in the policy model (daily/monthly quota, concurrency, schedules, validity, priority) is ECLOUD-side by design.

**How.** (1) Read every artifact's capability matrix, evidence index, open questions and device-test list. (2) Deduplicate identical claims across documents into one ledger row carrying the strongest label and all sources. (3) Where two documents disagree, record a conflict with a recommended resolution (§3). (4) Classify each non-verified row as blocking Phase 3 (foundation) or only Phases 5–7 (device-facing) (§4). (5) Turn every RDT/U row into a concrete device test (§5) and every design element into an automated test obligation (§6). No remote host or device was touched; no secret is recorded.

### 5.2 Test cases

Format: **Objective · Preconditions · Steps · Expected · Pass/Fail · Resolves (ledger) · Unblocks (decision).**

**DT-01 — Firmware inventory and uspot variant identification**
Objective: identify the uspot code base, ratelimit/spotfilter presence, WireGuard/unetd presence, schema version, radcli dictionaries. Preconditions: P1; read-only shell on the AP (via controller `remote_access`/rtty or SSH) — no writes. Steps: `cat /etc/openwrt_release; cat /etc/ucentral/ucentral.active | head -c 400` · `opkg list-installed | grep -iE 'uspot|spotfilter|ratelimit|wireguard|unetd|radius|hostapd|radcli'` · `ls /usr/share/uspot/ /etc/radcli/ 2>/dev/null; grep -l 'WISPr\|ChilliSpot' /etc/radcli/dictionary* 2>/dev/null` · `ubus list | grep -iE 'uspot|spotfilter|ratelimit|hostapd|unet'` · `ls /sys/module/wireguard 2>/dev/null; which wg` · `test -f /usr/share/uspot/handler-api.uc && echo UPSTREAM || echo TIP_FORK_LIKELY`. Expected: either (T) `spotfilter` + `ratelimit` objects, no `handler-api.uc`, or (U) `uspotfilter` + `handler-api.uc`. Pass: variant unambiguously classified and dictionary files located (or confirmed absent). Resolves: V-040, V-027, V-028, V-052 (dictionary), V-022 schema. Unblocks: **D-002**, D-010 (B feasibility), D-012 adapter default (C-04).

**DT-02 — Per-SSID `rate-limit` semantics and re-push side effects**
Objective: confirm per-station ceiling vs aggregate; interaction with a higher RADIUS rate; effect of re-push on live sessions. Preconditions: P1, P5 with `rate-limit{ingress-rate:5, egress-rate:10}` on `lab-mac` (no RADIUS rate). Steps: connect clients A and B; run `iperf3 -c <site-iperf> -t 20` (upload) and `-R` (download) on A alone, then A and B simultaneously; record Mbit/s; on the AP `tc -s class show dev <wlan>` and `ubus call ratelimit …` (read-only list if available); then on `lab-uam` with Accept `WISPr-Bandwidth-Max-Down=20000000` and SSID `egress-rate:10`, measure; finally re-push the identical config (`configure`) during an active uspot session and observe whether the portal session and `tc` classes survive. Expected: A alone ≈ 10/5; A+B each ≈ 10/5 (per-station) rather than 5/2.5 (aggregate); SSID ceiling clamps the 20 Mbit/s RADIUS value (or not — record); re-push resets uspot clients (V-019) and possibly tc state. Pass: measured within ±15 % of the predicted model and behaviour documented. Resolves: V-001 (on EZEAP), V-002, V-020. Unblocks: D-003 mechanism, PE D1 rationale, PE §5.3 batching rule.

**DT-03 — RADIUS attribute capture (Access-Request / Accounting) for all three NAS paths**
Objective: record exactly which attributes and formats each path sends. Preconditions: P1–P5; FreeRADIUS `-X` in the lab. Steps: trigger one login on each SSID (uspot UAM via portal, 802.1X via `wpa_supplicant` or phone, MAC-auth); capture with `tcpdump -ni wg0 -w dt03.pcap 'udp port 1812 or udp port 1813'`; `tshark -r dt03.pcap -V -Y radius | grep -E 'User-Name|NAS-Identifier|NAS-IP-Address|Called-Station|Calling-Station|Acct-Session-Id|Acct-Unique|Message-Authenticator|Service-Type|Vendor|Framed-IP|Acct-Status|Acct-Interim|Class'`; compare `NAS-IP-Address` with the UDP source; compare uspot `Acct-Session-Id` with the UAM `sessionid` captured in DT-11; dump vendor TLV 0000e608 bytes. Expected (per CP §3.4): uspot sends the V-048 set, `Called-Station-Id` = `nasmac:ssid`; hostapd sends `NAS-Identifier` when `radius.nas-identifier` set; presence/absence of attribute 80 recorded per path. Pass: a filled attribute matrix per path (template §5.4) with MAC spelling and separators. Resolves: V-032, V-048, V-049, V-047, V-025, V-072 (if gateway present), V-114 (source IP). Unblocks: D-004 tenant resolution (MT §3.3 A/C), BlastRADIUS per-NAS flag (AAA §8), accounting idempotency key, DB Q3.

**DT-04 — WISPr / ChilliSpot bandwidth honouring (uspot) measured with iperf3**
Objective: prove per-client rate from RADIUS on the captive path, direction mapping and family precedence. Preconditions: DT-01 done; `lab-uam` SSID with **no** `rate-limit`; FreeRADIUS lab policy returning fixed reply attributes per test user (`users` file in lab only). Steps: for users u2/u5/u20 with `WISPr-Bandwidth-Max-Down = 2000000|5000000|20000000`, `WISPr-Bandwidth-Max-Up = 1000000|2500000|10000000`: login via portal, run `iperf3 -c <site-iperf> -t 20 -R` (download) and without `-R` (upload); repeat with `ChilliSpot-Bandwidth-Max-Down = 5000` (kbit/s) alone; then with both families present (WISPr 20 M, ChilliSpot 5000) and record which applies; on the AP `tc -s class show dev <wlan>` for the client's MAC class. Expected: measured ≈ configured ±10 % (AAA T-A10); down→egress, up→ingress; precedence documented. Pass: all three rates within tolerance; if no shaping at all, check DT-01 dictionary result before declaring FAIL. Resolves: V-052, V-053, V-063. Unblocks: **D-003** per-client enforcement (DoD "actual bandwidth enforcement"), PE Q8 default, D-012 capability flip to `VERIFIED_DEVICE`.

**DT-05 — Session-Timeout / Idle-Timeout / Acct-Interim-Interval precedence and renderer default injection**

Steps: (a) Accept with `Session-Timeout=120`, `Idle-Timeout=60`, `Acct-Interim-Interval=30`, SSID without `acct-interval`: login, keep traffic flowing, time the Stop (expect ~120 s, cause 5); login again, go idle, time the Stop (~60–70 s, cause 4); measure Interim spacing in pcap; on the AP `uci show uspot | grep -i acct_interval` (read-only) to see whether the renderer injected 600.
